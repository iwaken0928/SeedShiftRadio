  - SeedShiftRadio 要件定義書（版：0.3）

## 1. 目的・範囲

本書は、SeedShiftRadioのUIを **「A案（三分割＋常時プレイヤー）」** のレイアウト方針で統一し、以下3画面の構成・表示要素・操作導線・状態表示・ViewModelバインディング指針を定義する。

- メイン画面（ラジオ）…A案レイアウト
- レター画面（投稿／一覧・管理／詳細）
- 設定画面（主設定 config.json／軽量ユーザー設定 user.config を包含）

実装はWPF（MVVM）を前提とし、将来のWinUI 3移行を阻害しないUI構造（UI責務をViewModelに閉じ込め、UseCase呼び出し中心）を採る。

---

## 2. 画面一覧とナビゲーション

### 2.1 トップレベルナビ

アプリ共通シェル（Shell）に、以下のトップレベルを持つ。

- **ラジオ**（メイン画面）
- **レター**（レター画面）
- **設定**（設定画面）

ナビゲーションは、WPFでは上部タブ／左ナビいずれでもよいが、将来WinUI 3の `NavigationView` へ移植しやすいよう、実装上は「選択中ページを差し替えるコンテンツ領域（ContentHost）」を中心に構成する。

### 2.2 画面遷移（概略）

- 起動時：ラジオ（メイン）を表示（前回局があれば復元）
- レター：メインナビから遷移。レター内は「一覧・管理」を初期表示
- 設定：メインナビから遷移

## 3. 共通UI設計（レイアウト・挙動）

### 3.1 共通フレーム（Shell）

- **上部ヘッダー（AppHeader）**
  - アプリ名（左）
  - トップレベルナビ（ラジオ／レター／設定）
  - 右側ステータス領域（プロバイダ状態、簡易エラー表示、同期/保存状態）

- **コンテンツ領域（ContentHost）**
  - 選択された画面のルートViewを表示

- **通知（非ブロッキング）**
  - トースト／スナックバー相当の領域（画面右下推奨）
  - 「止めない設計」に基づき、致命的でない失敗はモーダルを避ける

### 3.2 画面サイズ・リサイズ指針

- 最小ウィンドウサイズ（推奨）：**幅 1100px × 高さ 700px**
- メイン（A案）は3列構成のため、幅が狭い場合は右ペインを自動折りたたみ（Collapsed）し、字幕／キューは中央下に退避できる構造を用意する（将来対応も可）。
- 基本は `Grid` で構成し、列幅は
  - 左：固定（例：280px）または最小幅＋伸縮（Min 240 / Max 360）
  - 中央：残り幅（*）
  - 右：固定（例：360px）または伸縮（Min 280 / Max 420）
  - 下：固定（プレイヤー 72〜88px）

### 3.3 入力・アクセシビリティ（最低要件）

- キーボード操作：
  - Space：再生/一時停止
  - Ctrl + Left/Right：局スキャン（前/次）
  - Ctrl + L：レター画面へ
  - Ctrl + ,（カンマ）：設定画面へ
  - Esc：モーダル/ドロワーを閉じる
- フォーカス順：左→中央→右→下（視線誘導と一致）
- 主要コントロールに `AutomationProperties.Name` 相当のラベルを付与

## 4. 画面設計：メイン画面（ラジオ）— A案

### 4.1 目的

- 周波数（離散チャンネル）操作により局を切替
- トーク/音楽を連続再生し、現在の状態（局、番組、字幕、次キュー）を常時把握できること
- スキャン、字幕表示、履歴、放送中のレター表示（推奨）を自然に統合する

### 4.2 レイアウト（リージョン定義）

```
┌──────────────────────────────────────────────────────────────┐
│ AppHeader： [ラジオ] [レター] [設定]         Provider/Cache状態 │
├───────────────┬───────────────────────────┬───────────────────┤
│ 左ペイン       │ 中央ペイン                 │ 右ペイン           │
│ Station/操作   │ NowPlaying + Dial          │ 字幕/キュー/レター │
├───────────────┴───────────────────────────┴───────────────────┤
│ 常時プレイヤー（フッター）：再生/停止/音量/前後/状態            │
└──────────────────────────────────────────────────────────────┘
```

#### 左ペイン（Station/操作）
- 局一覧（周波数順）
  - 表示：周波数（MHz）、局名、ジャンル（任意）、簡易アイコン（任意）
  - 選択：クリックでチューン
- スキャン操作
  - 「前の局」「次の局」ボタン
- お気に入り（将来）
  - フィルタ切替（全局／お気に入り）

#### 中央ペイン（NowPlaying + Dial）
- 現在局カード（上部）
  - 局名、周波数、番組/セグメント種別、パーソナリティ名（表示名）
- 周波数ダイヤル（主操作）
  - MVP推奨：スライダー（離散スナップ）＋ノブ風ビジュアル
  - マウスホイール：前後チャンネル
- 進行表示（任意）
  - セグメント進行（トーク/音楽/コーナー）
  - バッファ状態（例：次セグメント準備 2/2）

#### 右ペイン（情報：タブ）
タブ構成（上部にTabControl）
- **字幕**：現在の発話テキスト（スクロール可、コピー可は任意）
- **キュー**：次に再生されるセグメント一覧（トーク/音楽/レター 等）
- **レター**：放送中に取り上げるレター（レターコーナー時に自動表示）
- （任意）履歴：聴取履歴（局/セグメント/曲）

#### フッター（常時プレイヤー）
- 再生/一時停止、停止
- 前/次（局スキャンと統一 or セグメントスキップとして別扱い）
- 音量スライダー、ミュート
- 字幕ON/OFFトグル（右ペイン折りたたみ時の代替導線）
- 状態表示：再生中／生成中／フォールバック中／オフライン等

### 4.3 主要状態とUI表現

| 状態 | 例 | 表現 |
|---|---|---|
| Idle | 未再生 | 中央に「再生を開始」ヒント、プレイヤーは操作可能 |
| Playing | 通常再生 | 再生アイコン、現在セグメント名、字幕更新 |
| Buffering/Generating | 次セグメント生成中 | バッファゲージ、右上に軽微なスピナー |
| Switching Station | 周波数変更直後 | 局カードを切替、キュー初期化、必要ならフェード/停止表示 |
| Fallback | LLM/TTS失敗 | 非ブロッキング通知＋状態バッジ（音は止めない） |

### 4.4 操作フロー（代表）

- 周波数変更（ダイヤル/スライダー）
  1) 変更開始（ドラッグ）中は「候補周波数」を表示
  2) リリースでスナップ → `TuneToFrequency` 実行
  3) Station切替：キュー初期化 → オープニング or 次セグメント再生開始

- スキャン（次/前）
  - ボタン/ショートカットで `ScanNext` / `ScanPrev` 実行

- 字幕確認
  - 右ペイン「字幕」タブ or フッターの字幕ボタンで表示切替

### 4.5 ViewModel（バインディング指針）

> 命名は例。WPF/WinUIで差し替えやすいよう、UI固有処理は `IUiDialogService` 等へ寄せる。

#### プロパティ（例）
- `double CurrentFrequencyMhz`
- `StationVm CurrentStation`
  - `string Name`, `string Genre`, `string PersonalityDisplayName`
- `ProgramVm NowPlaying`
  - `string SegmentType`, `string Title`, `TimeSpan? Remaining`
- `bool IsPlaying`
- `double Volume` / `bool IsMuted`
- `string CaptionText`
- `IReadOnlyList<QueueItemVm> QueueItems`
- `IReadOnlyList<HistoryItemVm> HistoryItems`（任意）
- `ProviderStatusVm ProviderStatus`（LLM/TTS）
- `BufferStatusVm BufferStatus`（例：`int ReadyCount`, `int TargetCount`）

#### コマンド（例）
- `ICommand TogglePlayPauseCommand`
- `ICommand StopCommand`
- `ICommand TuneToFrequencyCommand`（引数：frequency）
- `ICommand ScanNextCommand` / `ScanPrevCommand`
- `ICommand SetVolumeCommand`（引数：volume）
- `ICommand ToggleCaptionPaneCommand`
- `ICommand OpenLetterCommand`（レター画面へ）
- `ICommand ToggleRightPaneCommand`（狭幅時の折りたたみ）

## 5. 画面設計：レター画面

### 5.1 目的

- レター投稿（宛先局、件名、本文、任意ラジオネーム）
- レター一覧/管理（状態：未読/保留/採用/返信済、局別フィルタ、検索）
- レター詳細（本文、スレッド、放送での取り上げ履歴）
- 失敗時でも運用を止めない（返信生成失敗→保留にして再生成可能 等）

### 5.2 レイアウト（マスター・ディテール＋投稿導線）

```
┌────────────────────────────────────────────────────────┐
│ ヘッダー：フィルタ[局] [状態] [検索]   [＋新規投稿]      │
├──────────────────┬─────────────────────────────────────┤
│ 左：レター一覧     │ 右：レター詳細（本文＋スレッド）       │
│ ・状態バッジ       │ ・件名/宛先局/投稿者（ラジオネーム）    │
│ ・件名             │ ・本文                                 │
│ ・更新日時         │ ・スレッド（返信/追伸）                  │
│                   │ ・取り上げ履歴（任意）                   │
├──────────────────┴─────────────────────────────────────┤
│ フッター： [保留] [採用] [返信生成] [再生成] [放送で採用] │
└────────────────────────────────────────────────────────┘
```

#### 投稿（新規投稿）
- 原則：**モーダルダイアログ**（または別サブページ）で表示
- 項目：
  - 宛先局（コンボボックス）
  - 件名（テキスト）
  - 本文（複数行）
  - ラジオネーム（任意）
- 送信後：一覧へ追加し、ステータス「未読」で表示

### 5.3 主要UI要素

- フィルタ/検索
  - 局フィルタ：All/局名
  - 状態フィルタ：未読/保留/採用/返信済/すべて
  - 検索：件名・本文の全文検索（最初は件名/本文部分一致でも可）

- 一覧セル表示
  - 状態バッジ（色分けは任意）
  - 件名、宛先局、更新日時
  - 未読は太字

- 詳細表示
  - メタ情報（宛先局、投稿日時、ラジオネーム）
  - 本文
  - スレッド（時系列で表示、AI返信とユーザー追伸を区別）

### 5.4 状態とエラー表示

- 返信生成中：ボタンを一時無効化＋進行表示（右上の非ブロッキングスピナー）
- 返信生成失敗：
  - トースト通知（失敗理由の短文）
  - レター状態は「保留」に遷移（再生成可能）
- 放送で採用：採用フラグ更新＋（任意）採用演出予約

### 5.5 ViewModel（バインディング指針）

#### プロパティ（例）
- `ObservableCollection<LetterSummaryVm> Letters`
- `LetterSummaryVm? SelectedLetter`
- `LetterFilterVm Filter`
  - `StationId? Station`, `LetterStatus? Status`, `string? Query`
- `LetterDetailVm? Detail`
  - `string Subject`, `string Body`, `string? RadioName`, `IReadOnlyList<ThreadItemVm> Thread`
- `bool IsBusy`

#### コマンド（例）
- `ICommand CreateLetterCommand`（投稿ダイアログ起動）
- `ICommand SubmitLetterCommand`（投稿）
- `ICommand ChangeStatusCommand`（保留/採用/返信済等）
- `ICommand GenerateReplyCommand`
- `ICommand RegenerateReplyCommand`
- `ICommand MarkAsOnAirCommand`（放送内で取り上げ）

## 6. 画面設計：設定画面

### 6.1 目的

- LLM/TTSプロバイダの差し替え設定
- 音源フォルダ、キャッシュ設定
- 設定永続化（主設定：config.json、軽量設定：user.config）
- APIキー等の機密情報は参照方式（apiKeyRef）で保持

### 6.2 レイアウト（カテゴリ一覧＋詳細フォーム）

```
┌────────────────────────────────────────────────────────┐
│ ヘッダー：設定   [主設定: config.json パス] [保存] [エクスポート] │
├──────────────────┬─────────────────────────────────────┤
│ 左：カテゴリ       │ 右：設定フォーム                       │
│ ・全般            │ ・各項目（入力/説明/検証）               │
│ ・再生            │ ・注意/警告（apiKey直書き禁止など）       │
│ ・LLM             │                                         │
│ ・TTS(A.I.VOICE)  │                                         │
│ ・音源            │                                         │
│ ・キャッシュ       │                                         │
│ ・エクスポート/インポート │                                  │
└──────────────────┴─────────────────────────────────────┘
```

### 6.3 設定の区分（表示ルール）

- **主設定（config.json）**
  - 共有/移植したい設定（Station定義、周波数、seed、編成、音源ルール、レター方針、LLM/TTS設定 等）
  - UI上で「主設定」バッジを表示
  - エクスポート/インポート機能を提供

- **軽量ユーザー設定（user.config）**
  - 端末依存のUI状態（ウィンドウサイズ、最終局、音量、右ペイン開閉状態 等）
  - UI上で「端末設定」バッジを表示（任意）

### 6.4 カテゴリ別項目（推奨）

#### 全般
- 主設定ファイルパス（開く/参照）
- 言語、起動時の初期局（任意）
- UI：右ペイン既定表示、字幕既定ON/OFF

#### 再生
- セグメント長（秒）※方針に沿って範囲制限
- 先読みバッファ数
- 既定音量、ミュート開始（任意）

#### LLM
- providerType（例：OpenAI互換／ローカル互換）
- baseUrl / model
- apiKeyRef（環境変数名 等）
- 接続テスト（任意：軽量な疎通）

#### TTS（A.I.VOICE）
- providerType：AIVoice
- 話者、音量/話速/高さ（対応範囲）
- デバイス/出力先（任意）
- 接続テスト（短いテキスト再生）

#### 音源
- 音源フォルダ（複数可）
- 対象拡張子、シャッフル条件（任意）
- スキャン/再読込

#### キャッシュ
- キャッシュON/OFF
- TTL、最大容量、削除ポリシー
- 「キャッシュ削除」ボタン

#### エクスポート/インポート
- 主設定のエクスポート/インポート
- バリデーション（schemaVersion、必須項目）

### 6.5 保存・適用の挙動

- 変更検知：未保存バッジ表示
- 保存：
  - 主設定：config.jsonを書き換え
  - 軽量設定：user.configへ書き込み
- 反映：
  - 反映に再生再初期化が必要な項目（LLM/TTS）には注意文を表示し、必要なら「再接続」ボタンを提供

### 6.6 ViewModel（バインディング指針）

- `SettingsShellVm`
  - `string ConfigPath`
  - `bool HasUnsavedChanges`
  - `CategoryVm SelectedCategory`
- コマンド：
  - `SaveCommand`
  - `ExportConfigCommand` / `ImportConfigCommand`
  - `BrowseConfigPathCommand`（`IUiDialogService`）
  - `TestLlmCommand` / `TestTtsCommand`
  - `ClearCacheCommand`

## 7. 非機能：通知・ログ・運用性（UI観点）

- 生成失敗・フォールバックは「モーダルで止めない」
- 重要イベントはステータス領域に短い表示（例：TTS失敗→BGM延長）
- 詳細はログ画面（将来）またはログファイルで追跡可能とする

---

## 8. WinUI 3移行を見据えた実装注意

- UIはViewModelで完結し、UseCase呼び出しのみを行う
- UI固有要素（ファイルピッカー、通知、ダイヤル操作差異）は `IUiDialogService` / `INotificationService` 等で抽象化し、WPF実装／WinUI実装を差し替え可能にする
- レイアウトは「ナビ＋コンテンツ領域＋常時プレイヤー」の骨格を固定し、コントロール差異を局所化する
