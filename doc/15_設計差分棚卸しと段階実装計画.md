# SeedShiftRadio 設計機能・実装対応・残タスク整理

## 1. 目的

本書は [00_実装ドキュメント一覧.md](./00_実装ドキュメント一覧.md) で定義した設計書群に対して、現時点の設計機能、実装状況、機能とコードの対応、残りの実装タスクを一か所で確認できるように整理した棚卸し資料である。

今後の実装では、本書の `残タスク` を起点にし、挙動や契約を変える場合は該当する `doc/02` から `doc/14` も同時に更新する。

前提:

- 調査日: 2026-04-18
- Irodori-TTS 追加調査日: 2026-05-16
- 設計正本: `doc/00` から `doc/14`
- 現行 Server 実装: `src/main/java/com/seedshiftradio/**`
- 現行 Web 実装: `web/`
- 現行 MusicGen worker 実装: `workers/musicgen/`
- `/server` への物理分離と `/infra/compose` は未作成
- `web/node_modules`, `web/.next`, `build`, `bin` などの生成物は実装対応の評価対象外

状態の定義:

| 状態 | 意味 |
|---|---|
| `実装済み` | 設計の MVP 要件を満たす実装と主要テストがある |
| `部分実装` | API や骨格はあるが、実 provider、運用、UI、テスト、縮退などに未完部分がある |
| `未着手` | 設計上の機能に対応する現物がほぼない |

## 2. 現状結論

現在は `サーバー正本`, `REST API`, `SSE`, `DB migration`, `基本 playout`, `letter workflow`, `programming policy`, `settings`, `provider health`, `generated asset`, `MusicGen worker 契約`, `Next.js 主要画面` まで到達している。MVP の土台はかなり進んでいる。

一方で、残実装の中心は次の 5 つである。

| 領域 | 現状 | 残りの重点 |
|---|---|---|
| LLM / TTS | `ScriptGenerationService` と script asset はあるが、LLM は `TemplateScriptProvider`。TTS は `HttpTtsProvider` で VOICEVOX `/audio_query` + `/synthesis` と Irodori OpenAI互換 `/v1/audio/speech` を呼び出し、失敗時は provider chain から fallback、最後に placeholder へ縮退する。TTS audio metadata は本文を持たず hash と短い診断値へ制限済み | Ollama/OpenAI 互換 adapter、VoiceProfile metadata 拡張、Irodori speed/providerOptions/参照音声同意の runtime 反映、LETTER 回答案生成 |
| MusicGen | Server 側 gateway は `MUSICGEN_WORKER` / `ACE_STEP` に対応。worker は deterministic / failing backend。`MUSIC_AI` 失敗時は `paths.musicLibrary` の `.wav` または jingle へ縮退継続し、worker contract test は GitLab CI `worker-contract` job で実行する | worker 実モデル backend、モデル license/運用メモ |
| Playout / Programming | ready count / duration / prepared blocks は設定反映済み。`composition.maxConsecutiveTalkSegments`, `musicBreakIntervalMinutes`, `letterPriorityBoostThreshold`, `allowSoftFallbackRetiming`, `targetSegmentShares` は runtime 反映済み。`replay.maxReplaySharePercent` も block 単位で反映済み。`preGeneration.mode`, `maxPreparedMinutes`, `maxPreparedBlocks`, `preferCacheReuse` は queue planning / reusable asset 選択へ反映済み。`musicAheadCount` は current block 優先と preGeneration mode ごとの future block 窓を含めて runtime 反映済み。`scriptAheadCount` / `ttsAheadCount` も future spoken queue item の prefetch 深さへ反映済み。`LETTER` は current block の最初の upcoming letter 1 件だけを ahead 対象にする運用まで反映済み。`idlePrefetchEnabled` も manual play 待機中の extra prefetch 抑制として反映済み。さらに `QueuePreparationPolicy` 相当で ready count / duration / blocks / ahead count の有効値計算を集中管理済み | なし |
| Cache / Archive / Monitor | `generated_asset` lifecycle、payload eviction job、cache metrics、asset consistency 検査、archive pool / replay rate、`broadcast_archive` はある | 監査永続化 |
| Web / Infra / CI | 主要 4 画面、SSE/audio、Vitest unit test、Playwright mock E2E、`/settings` Import / Export、station 基本情報 / programming policy editor、provider health 表示 redaction、`/infra/compose`、`.env.example`、ローカル起動ガイド、統合 smoke script、GitLab CI `.gitlab-ci.yml` に `server-unit` / `server-docker` / `web-typecheck` / `web-unit` / `web-e2e` / `worker-contract` / `gpu-smoke` / `deploy-musicgen` を定義済みで、test 系は `podman --remote run` の toolchain container で実行する | compose 上の実 provider 運用メモ、server / web の deploy 自動化範囲拡張 |

## 8. 残実装タスク

### 8.1 P0: 実生成系を placeholder から脱却する

目的:

- TALK / LETTER / MUSIC_AI を実 provider または明示 fallback の音声で成立させる
- 「契約だけ満たす」段階から「実際に聴ける MVP」へ進める

タスク:

1. `P0-01` LLM adapter を追加する
   - 対象: `ScriptProvider`, `ProviderRegistry`, `ProviderJobService`, `SettingsDocument.providers.llm`

## 12. 実装時の注意点

- API, DTO, SSE を変える場合は `doc/02` を同時更新する
- Web 画面、状態、音声再生、SSE 購読を変える場合は `doc/03` を同時更新する
- DB, `config.json`, asset path, cache policy を変える場合は `doc/04` を同時更新する
- queue, fallback, playout, JobRunr を変える場合は `doc/05` と必要に応じて `doc/11` を同時更新する
- LLM/TTS/読み辞書/persona/speech directive を変える場合は `doc/06`, `doc/07`, `doc/08` を同時更新する
- MusicGen worker 契約を変える場合は `doc/09` を同時更新する
- レター状態や放送採用フローを変える場合は `doc/12` を同時更新する
- C# Native Client と共有する契約は `doc/10` と照合して壊さない
