## 4. `P0-10` 修正内容

対象:

- `HttpTtsProvider.resolveAdapter`
- `HttpTtsProviderTests`
- queue warmup を含む `RadioApiTests`

修正後の規則:

1. Provider 設定に明示 adapter があれば、その adapter を使う。
2. provider key が `seedshift-placeholder` なら、voice hint を解釈せず placeholder を使う。
3. それ以外でだけ voice hint、capability、provider key から VOICEVOX / Irodori を推定する。

この順序により、外部 provider の失敗後も最終縮退が再び外部接続へ戻らず、queue item を再生可能な placeholder asset へ収束させる。

## 8. 完了判定

各 Issue は次を満たした時だけ完了とする。

- 受け入れ条件を満たす実装と focused test がある。
- 関係する設計書が実装と一致している。
- 秘密値、レター本文、prompt、radioName を標準ログや client bundle へ露出していない。
- Server、Web、worker、CI のうち変更範囲に対応する test が成功している。
- 残課題を同じ変更へ混ぜず、既存 Issue または新規 Issue で追跡している。
- メインエージェントが差分と最終 test を確認し、GitLab Issue に検証結果を記録している。
