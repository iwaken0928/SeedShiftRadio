# SeedShiftRadio 設計機能・実装対応・残タスク整理

## 1. 目的

本書は [00_実装ドキュメント一覧.md](./00_実装ドキュメント一覧.md) で定義した設計書群に対して、現時点の設計機能、実装状況、機能とコードの対応、残りの実装タスクを一か所で確認できるように整理した棚卸し資料である。

今後の実装では、本書の `残タスク` を起点にし、挙動や契約を変える場合は該当する `doc/02` から `doc/14` も同時に更新する。

前提:

- 調査日: 2026-04-18
- 設計正本: `doc/00` から `doc/14`
- 現行 Server 実装: `src/main/java/com/seedshiftradio/**`
- 現行 Web 実装: `web/`
- 現行 MusicGen worker 実装: `workers/musicgen/`
- `/server` への物理分離と `/infra/compose` は未作成
- `web/node_modules`, `web/.next`, `build`, `bin` などの生成物は実装対応の評価対象外

状態の定義:

| 状態 | 意味 |
|---|---|
| `実装済み` | 設計の MVP 要件を満たす実装と主要テストがある |
| `部分実装` | API や骨格はあるが、実 provider、運用、UI、テスト、縮退などに未完部分がある |
| `未着手` | 設計上の機能に対応する現物がほぼない |

## 2. 現状結論

現在は `サーバー正本`, `REST API`, `SSE`, `DB migration`, `基本 playout`, `letter workflow`, `programming policy`, `settings`, `provider health`, `generated asset`, `MusicGen worker 契約`, `Next.js 主要画面` まで到達している。MVP の土台はかなり進んでいる。

一方で、残実装の中心は次の 5 つである。

| 領域 | 現状 | 残りの重点 |
|---|---|---|
| LLM / TTS | `ScriptGenerationService` と script asset はあるが、LLM は `TemplateScriptProvider`、TTS は `PlaceholderTtsProvider` | Ollama/OpenAI 互換 adapter、VOICEVOX adapter、LETTER 回答案生成 |
| MusicGen | Server 側 gateway は `MUSICGEN_WORKER` / `ACE_STEP` に対応。worker は deterministic / failing backend | worker 実モデル backend、worker contract CI、`MUSIC_LOCAL` / jingle への実音源 fallback |
| Playout / Programming | ready count / duration / prepared blocks は設定反映済み | `scriptAheadCount`, `ttsAheadCount`, `musicAheadCount`, `preGeneration`, `composition`, `maxReplaySharePercent` の runtime 反映 |
| Cache / Archive / Monitor | `generated_asset` lifecycle、payload eviction job、cache metrics、asset consistency 検査、archive pool / replay rate、`broadcast_archive` はある | block 単位 replay share、監査永続化 |
| Web / Infra / CI | 主要 4 画面、SSE/audio、Vitest unit test、Playwright mock E2E、`/settings` Import / Export、station 基本情報 / programming policy editor、provider health 表示 redaction はある | `/infra/compose`、CI job 分割 |

## 8. 残実装タスク

### 8.1 P0: 実生成系を placeholder から脱却する

目的:

- TALK / LETTER / MUSIC_AI を実 provider または明示 fallback の音声で成立させる
- 「契約だけ満たす」段階から「実際に聴ける MVP」へ進める

タスク:

1. `P0-01` LLM adapter を追加する
   - 対象: `ScriptProvider`, `ProviderRegistry`, `ProviderJobService`, `SettingsDocument.providers.llm`
   - 候補: Ollama adapter、OpenAI 互換 HTTP adapter
   - 完了条件: `TemplateScriptProvider` ではなく実 provider から `GeneratedScript` を生成できる
2. `P0-02` VOICEVOX TTS adapter を追加する
   - 対象: `TtsProvider`, `AssetService`, `SettingsDocument.providers.tts`
   - 完了条件: TALK / LETTER の queue item が実 WAV asset を持つ
3. `P0-03` script -> normalize -> quality guard -> TTS -> asset の orchestration を明示 service へ分離する
   - 対象: `AssetService`, `ScriptGenerationService`
   - 完了条件: script asset と tts asset の provider job / metadata / cache key を追跡できる
4. `P0-04` LETTER 回答案生成を実装する
   - 対象: `doc/06`, `doc/12`, `LetterService`, `ScriptGenerationService`
   - 完了条件: letter body を信頼せず、要約と引用を分けて安全に台本化できる
5. `P0-05` provider error と fallback 連鎖を統一する
   - 対象: LLM/TTS/MUSIC の adapter 共通 result/error
   - 完了条件: timeout / unreachable / bad response / safety blocked が `provider_job.errorCode` と degraded reason へ揃う

### 8.2 P0: MusicGen 実運用と縮退継続

1. `P0-06` `workers/musicgen` に実モデル backend を追加する
2. `P0-07` worker contract test を server / worker 両方で固定する
3. `P0-08` MusicGen 失敗時の実音源 fallback を実装する
4. `P0-09` ACE-Step 運用設定を compose / settings / docs へ接続する

完了条件:

- deterministic 以外の backend で WAV を生成できる
- `MUSIC_AI` 失敗時に `MUSIC_LOCAL` または jingle が `READY` になり、無音停止しない
- Server から ACE-Step または worker へ疎通できる手順がある

### 8.3 P1: playout / programming runtime を設計値へ寄せる

1. `P1-01` `QueuePreparationPolicy` 相当を追加し、ready count / duration / blocks / ahead count を集中管理する
2. `P1-02` `scriptAheadCount`, `ttsAheadCount`, `musicAheadCount` を segment type ごとの生成深さへ反映する
3. `P1-03` `preGeneration` profile を queue planning へ反映する
4. `P1-04` `composition` profile を runtime へ反映する
5. `P1-05` `maxReplaySharePercent` を block 単位で enforce する
6. `P1-06` `ProgrammingAdminService.preview` と `ProgrammingService.resolveCurrentPlan` のロジック差分を整理する

## 12. 実装時の注意点

- API, DTO, SSE を変える場合は `doc/02` を同時更新する
- Web 画面、状態、音声再生、SSE 購読を変える場合は `doc/03` を同時更新する
- DB, `config.json`, asset path, cache policy を変える場合は `doc/04` を同時更新する
- queue, fallback, playout, JobRunr を変える場合は `doc/05` と必要に応じて `doc/11` を同時更新する
- LLM/TTS/読み辞書/persona/speech directive を変える場合は `doc/06`, `doc/07`, `doc/08` を同時更新する
- MusicGen worker 契約を変える場合は `doc/09` を同時更新する
- レター状態や放送採用フローを変える場合は `doc/12` を同時更新する
- C# Native Client と共有する契約は `doc/10` と照合して壊さない
