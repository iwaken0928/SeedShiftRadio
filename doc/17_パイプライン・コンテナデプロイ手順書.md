# パイプライン・コンテナデプロイ手順書

## 1. 目的

本書は SeedShiftRadio の `server` / `web` を GitLab CI/CD と Podman Compose でビルド・デプロイするための作業手順をまとめる。詳細な仕様判断は [16_パイプライン・コンテナデプロイ仕様書.md](./16_パイプライン・コンテナデプロイ仕様書.md) を正本とし、本書は運用時に確認する手順書として扱う。

構成の前提:

- GitLab Runner はデプロイ先サーバー上で動作する
- コンテナ操作は `podman --remote` / `podman --remote compose`
- PostgreSQL は compose 内に作らず、同一ホスト上の既存 PostgreSQL を使う
- `server` は標準で `127.0.0.1:8080` に bind する
- `web` は host network で `0.0.0.0:3000` を直接公開する
- Web から Server への API/SSE は `/api-proxy` 経由で中継する

## 2. 初回準備

### 2.1 PostgreSQL

デプロイ前に PostgreSQL 側で以下を用意する。

- DB: `SEEDSHIFT_RADIO_DB_NAME`（既定値: `seedshift_radio`）
- DB ユーザー: `SEEDSHIFT_RADIO_DB_USERNAME`（既定値: `seedshift`）
- DB パスワード: `SEEDSHIFT_RADIO_DB_PASSWORD`
- migration 実行に必要な schema 作成・変更権限
- 接続先は標準で `127.0.0.1:5432`

確認例:

```sh
psql -h 127.0.0.1 -p 5432 -U <db-user> -d <db-name> -c 'select 1;'
```

### 2.2 Runner / Podman

Runner host で以下を確認する。

```sh
podman --remote info
podman --remote compose version
```

デプロイ job は `tags: [shared, deploy]` の Runner で実行される。test / build 系 job は `tags: [shared, shell]` を使う。

### 2.3 Firewall

Web を直接公開するため、利用者の接続元から `3000/tcp` へ到達できるようにする。Server API の `8080/tcp` は標準では `127.0.0.1` bind のため外部公開しない。

## 3. GitLab CI/CD Variables

GitLab の `Settings > CI/CD > Variables` に登録する。秘密値は `Masked` と `Protected` を付ける。

### 3.1 必須

| 変数 | 例 | 説明 |
|---|---|---|
| `SEEDSHIFT_RADIO_DB_PASSWORD` | 非掲載 | DB パスワード。masked/protected 推奨 |
| `SEEDSHIFT_ADMIN_TOKEN` | 非掲載 | 管理 API 用 token。masked/protected 推奨 |
| `SEEDSHIFT_WEB_ADMIN_PASSWORD` | 非掲載 | 管理 UI ログイン用。masked/protected 必須 |
| `SEEDSHIFT_WEB_SESSION_SECRET` | 非掲載 | session 署名用の高エントロピーなランダム値。masked/protected 必須 |

### 3.2 推奨

| 変数 | 既定値 | 説明 |
|---|---|---|
| `SEEDSHIFT_RADIO_DB_NAME` | `seedshift_radio` | 接続先 PostgreSQL DB 名。既定値と異なる場合のみ設定 |
| `SEEDSHIFT_RADIO_DB_USERNAME` | `seedshift` | DB ユーザー。既定値と異なる場合のみ設定 |
| `SEEDSHIFT_RADIO_DB_HOST` | `127.0.0.1` | PostgreSQL host |
| `SEEDSHIFT_RADIO_DB_PORT` | `5432` | PostgreSQL port |
| `SEEDSHIFT_RADIO_SERVER_PORT` | `8080` | Server port |
| `SEEDSHIFT_WEB_PORT` | `3000` | Web port |
| `SEEDSHIFT_DEPLOY_DIR` | `$HOME/seedshift-radio-deploy` | deploy runner 上の compose/env 配置先 |
| `SEEDSHIFT_RADIO_DATA_VOLUME` | `seedshift-radio-data` | Server data volume。通常は Podman managed volume |
| `SEEDSHIFT_RADIO_CONFIG_PATH` | `/var/lib/seedshift-radio/config/config.json` | Server container 内の config path |
| `SEEDSHIFT_RADIO_JOBRUNR_ENABLED` | `true` | 通常起動時の JobRunr 有効化 |
| `SERVER_INTERNAL_API_BASE_URL` | `http://127.0.0.1:8080` | Web container から Server へ中継する内部 URL |

`SEEDSHIFT_ADMIN_TOKEN`, `SEEDSHIFT_WEB_ADMIN_PASSWORD`, `SEEDSHIFT_WEB_SESSION_SECRET` は Web process の server-side 環境変数として使う。`NEXT_PUBLIC_*` へ設定せず、Web image の build arg にも渡さない。session secret の変更時は既存管理 session がすべて無効になる。

### 3.3 Image / Registry

| 変数 | 既定値 | 説明 |
|---|---|---|
| `SEEDSHIFT_LOCAL_IMAGE_REPOSITORY` | `localhost/seedshift-radio` | registry 未設定時の local image repository |
| `SEEDSHIFT_IMAGE_REPOSITORY` | `CI_REGISTRY_IMAGE` または local fallback | publish/deploy で使う image repository |
| `CI_REGISTRY` | GitLab 提供値 | 設定されている場合のみ `podman login` / `push` / `pull` を行う |
| `CI_REGISTRY_USER` | GitLab 提供値 | registry user |
| `CI_REGISTRY_PASSWORD` | GitLab 提供値 | registry password |

GitLab Container Registry が無効で `CI_REGISTRY` / `CI_REGISTRY_IMAGE` が空の場合、pipeline は `localhost/seedshift-radio` に fallback する。この場合 `publish` job は registry push を行わず、同一 Podman 環境の local image を `deploy` で使う。

外部 registry へ push したい場合だけ、`SEEDSHIFT_IMAGE_REPOSITORY`, `CI_REGISTRY`, `CI_REGISTRY_USER`, `CI_REGISTRY_PASSWORD` を設定する。

### 3.4 Smoke test

| 変数 | 既定値 | 説明 |
|---|---|---|
| `SEEDSHIFT_SMOKE_API_BASE_URL` | `http://127.0.0.1:8080` | Server health 確認先 |
| `SEEDSHIFT_SMOKE_WEB_BASE_URL` | `http://127.0.0.1:3000` | Web 表示確認先 |
| `SEEDSHIFT_SMOKE_WEB_API_PROXY_BASE_URL` | `http://127.0.0.1:3000/api-proxy` | Web proxy 経由 API 確認先 |

外部からの表示確認を行う場合でも、pipeline 上の smoke は Runner host から実行される。必要に応じて Runner host から到達可能な URL に上書きする。

### 3.5 MusicGen deploy

| 変数 | 既定値 | 説明 |
|---|---|---|
| `MUSICGEN_CONTAINER_NAME` | `seedshift-radio-musicgen` | MusicGen worker container 名 |
| `MUSICGEN_IMAGE_NAME` | `localhost/seedshift-radio/musicgen:<commit-sha>` | `deploy-musicgen` で build / run する image 名 |
| `MUSICGEN_HOST_BIND` | `0.0.0.0` | worker 公開 bind address |
| `MUSICGEN_HOST_PORT` | `28080` | worker 公開 port |
| `MUSICGEN_DATA_VOLUME` | 未設定 | 設定時だけ `/data` へ mount する Podman volume 名または絶対 host path |

`MUSICGEN_DATA_VOLUME` 未設定時は従来どおり container-local の一時領域を使う。生成物を pipeline 更新後も残す場合は GitLab CI/CD Variables に `MUSICGEN_DATA_VOLUME` を登録し、host path を使うときは事前に directory、所有者、権限、backup 方針を準備する。

### 3.5.1 Irodori-TTS deploy 候補

Irodori-TTS は現時点では必須 deploy job ではなく、TTS 実 provider 実装後に `deploy-irodori-tts` として追加する候補である。設計上の変数は以下とする。

| 変数 | 既定値 | 説明 |
|---|---|---|
| `IRODORI_TTS_IMAGE_NAME` | `localhost/seedshift-radio/irodori-tts:latest` | Irodori-TTS-Server image 名 |
| `IRODORI_TTS_HOST_BIND` | `127.0.0.1` | OpenAI互換 TTS server の bind address |
| `IRODORI_TTS_HOST_PORT` | `8088` | OpenAI互換 TTS server の port |
| `IRODORI_TTS_VOICES_VOLUME` | 未設定 | 承認済み参照音声を `voices/` へ mount する Podman volume 名または絶対 host path |
| `IRODORI_TTS_MODEL_VOLUME` | `seedshift-radio-irodori-models` | Hugging Face model cache 用 volume |
| `IRODORI_TTS_API_KEY` | 未設定 | optional bearer token。外部 bind 時は必須 |

標準は `127.0.0.1:8088` bind とし、Server の `providers.tts.providers.irodori.baseUrl` からのみ利用する。外部公開が必要な場合は `IRODORI_TTS_API_KEY`、firewall、許可元制限を必ず設定する。`IRODORI_TTS_VOICES_VOLUME` には本人または権利者の同意済み参照音声だけを置き、file 名に実名や秘密情報を含めない。

### 3.6 Job 別の必要変数

凡例:

- `必須`: 未設定だと job が失敗する、または目的の deploy ができない
- `条件付き`: registry 利用時、URL 変更時など特定構成で必要
- `任意`: 未設定なら既定値で動く
- `不要`: 通常は設定しない

| job | 必須 | 条件付き | 任意 / 既定値あり | 不要 / 備考 |
|---|---|---|---|---|
| `ci-yaml-validate` | なし | なし | `PODMAN_TEST_RUBY_IMAGE` | CI YAML の構文確認のみ |
| `compose-prod-validate` | なし | なし | DB、管理 token、Web 認証変数は job 内 dummy 値を使用 | 本番 DB には接続しない |
| `server-unit` | なし | なし | `PODMAN_TEST_JAVA_IMAGE`, `GRADLE_USER_HOME` | DB は test 設定に従う |
| `api-contract` | なし | なし | `PODMAN_TEST_JAVA_IMAGE`, `GRADLE_USER_HOME` | `./gradlew apiContractTest` で OpenAPI snapshot、認証マトリクス、`doc/02` を照合 |
| `server-docker` | なし | `PODMAN_REMOTE_SOCKET_PATH` は自動検出不可時のみ指定 | `PODMAN_TEST_JAVA_IMAGE`, `TESTCONTAINERS_*` | Testcontainers 用 |
| `web-typecheck` | なし | なし | `PODMAN_TEST_NODE_IMAGE` | API へ接続しない |
| `web-unit` | なし | なし | `PODMAN_TEST_NODE_IMAGE` | API は mock / test 前提 |
| `web-e2e` | なし | なし | `PODMAN_TEST_PLAYWRIGHT_IMAGE`、job 内の `PLAYWRIGHT_BASE_URL` と `E2E_*` test 専用値 | production 用 `SEEDSHIFT_*` は渡さない。standalone Web server を起動し、実 Server 起動は前提にしない |
| `worker-contract` | なし | なし | `PODMAN_TEST_PYTHON_IMAGE` | MusicGen worker contract test |
| `server-container-build` | なし | なし | `SEEDSHIFT_LOCAL_IMAGE_REPOSITORY` | local build tag を作るだけ |
| `web-container-build` | なし | なし | `SEEDSHIFT_LOCAL_IMAGE_REPOSITORY` | browser API base は same-origin `/api-proxy` 固定。local build tag を作るだけ |
| `server-container-publish` | なし | registry push する場合は `CI_REGISTRY`, `CI_REGISTRY_USER`, `CI_REGISTRY_PASSWORD`, `SEEDSHIFT_IMAGE_REPOSITORY` | `SEEDSHIFT_LOCAL_IMAGE_REPOSITORY` | registry 未設定時は local image を保持 |
| `web-container-publish` | なし | registry push する場合は `CI_REGISTRY`, `CI_REGISTRY_USER`, `CI_REGISTRY_PASSWORD`, `SEEDSHIFT_IMAGE_REPOSITORY` | `SEEDSHIFT_LOCAL_IMAGE_REPOSITORY` | registry 未設定時は local image を保持 |
| `deploy-migrate` | `SEEDSHIFT_RADIO_DB_PASSWORD`, `SEEDSHIFT_ADMIN_TOKEN` | registry から pull する場合は `CI_REGISTRY`, `CI_REGISTRY_USER`, `CI_REGISTRY_PASSWORD`, `SEEDSHIFT_IMAGE_REPOSITORY` | `SEEDSHIFT_RADIO_DB_NAME`, `SEEDSHIFT_RADIO_DB_USERNAME`, `SEEDSHIFT_RADIO_DB_HOST`, `SEEDSHIFT_RADIO_DB_PORT`, `SEEDSHIFT_LOCAL_IMAGE_REPOSITORY` | `main` manual job |
| `deploy-app` | `SEEDSHIFT_RADIO_DB_PASSWORD`, `SEEDSHIFT_ADMIN_TOKEN`, `SEEDSHIFT_WEB_ADMIN_PASSWORD`, `SEEDSHIFT_WEB_SESSION_SECRET` | registry から pull する場合は `CI_REGISTRY`, `CI_REGISTRY_USER`, `CI_REGISTRY_PASSWORD`, `SEEDSHIFT_IMAGE_REPOSITORY`; host path 固定時は `SEEDSHIFT_RADIO_DATA_VOLUME` | `SEEDSHIFT_DEPLOY_DIR`, `SEEDSHIFT_RADIO_DB_NAME`, `SEEDSHIFT_RADIO_DB_USERNAME`, `SEEDSHIFT_RADIO_DB_HOST`, `SEEDSHIFT_RADIO_DB_PORT`, `SEEDSHIFT_RADIO_SERVER_PORT`, `SEEDSHIFT_WEB_PORT`, `SEEDSHIFT_RADIO_CONFIG_PATH`, `SEEDSHIFT_RADIO_JOBRUNR_ENABLED`, `SERVER_INTERNAL_API_BASE_URL` | `main` manual job |
| `smoke-production` | `SEEDSHIFT_WEB_ADMIN_PASSWORD` | 公開 port / host を変える場合は `SEEDSHIFT_SMOKE_API_BASE_URL`, `SEEDSHIFT_SMOKE_WEB_BASE_URL`, `SEEDSHIFT_SMOKE_WEB_API_PROXY_BASE_URL` | `SEEDSHIFT_SERVER_CONTAINER_NAME`, `SEEDSHIFT_WEB_CONTAINER_NAME` | password はログへ出さず、Runner host から session / CSRF / proxy を確認 |
| `pipeline-docs-check` | なし | なし | なし | docs の存在と主要語句を確認 |
| `deploy-musicgen` | なし | port / bind 変更時は `MUSICGEN_HOST_BIND`, `MUSICGEN_HOST_PORT`; image 名変更時は `MUSICGEN_IMAGE_NAME`; 生成物を残す場合は `MUSICGEN_DATA_VOLUME` | `MUSICGEN_CONTAINER_NAME` | `MUSICGEN_DATA_VOLUME` 未設定時は container-local `/data` |
| 将来 `deploy-irodori-tts` | なし | 外部 bind 時は `IRODORI_TTS_API_KEY`; port / bind 変更時は `IRODORI_TTS_HOST_BIND`, `IRODORI_TTS_HOST_PORT`; image 名変更時は `IRODORI_TTS_IMAGE_NAME`; 参照音声を使う場合は `IRODORI_TTS_VOICES_VOLUME` | `IRODORI_TTS_MODEL_VOLUME` | GPU 利用時は Runner host の NVIDIA / Podman GPU 設定が必要 |

最小構成で GitLab CI/CD Variables として登録が必要なのは次の秘密値4つである。`deploy-migrate` は DB password と管理 token の2つだけを使い、`deploy-app` は Web の login password と session secret も要求する。DB 名と DB ユーザーは `.gitlab-ci.yml` の既定値 `seedshift_radio` / `seedshift` を使い、既存 PostgreSQL の設定が異なる場合だけ上書きする。

```text
SEEDSHIFT_RADIO_DB_PASSWORD
SEEDSHIFT_ADMIN_TOKEN
SEEDSHIFT_WEB_ADMIN_PASSWORD
SEEDSHIFT_WEB_SESSION_SECRET
```

registry へ push / pull する構成だけ、以下を追加する。

```text
SEEDSHIFT_IMAGE_REPOSITORY
CI_REGISTRY
CI_REGISTRY_USER
CI_REGISTRY_PASSWORD
```

### 3.7 設定例

#### 3.7.1 最小構成 local image fallback

GitLab Container Registry を使わず、デプロイ先サーバー上の同一 Podman 環境に image を残して deploy する構成。現在の Runner 構成ではこの形が一番少ない設定で動かせる。

| 変数 | 設定例 | 備考 |
|---|---|---|
| `SEEDSHIFT_RADIO_DB_NAME` | `seedshift_radio` | 既定どおりなら省略可 |
| `SEEDSHIFT_RADIO_DB_USERNAME` | `seedshift` | 既定どおりなら省略可 |
| `SEEDSHIFT_RADIO_DB_PASSWORD` | `********` | 必須。Masked / Protected |
| `SEEDSHIFT_ADMIN_TOKEN` | `********` | 必須。Masked / Protected |
| `SEEDSHIFT_WEB_ADMIN_PASSWORD` | `********` | 必須。Masked / Protected |
| `SEEDSHIFT_WEB_SESSION_SECRET` | `********` | 必須。32 byte 以上を目安にランダム生成し Masked / Protected |
| `SEEDSHIFT_RADIO_DB_HOST` | `127.0.0.1` | 既定どおりなら省略可 |
| `SEEDSHIFT_RADIO_DB_PORT` | `5432` | 既定どおりなら省略可 |
| `SEEDSHIFT_WEB_PORT` | `3000` | 既定どおりなら省略可 |
| `SEEDSHIFT_SMOKE_WEB_BASE_URL` | `http://127.0.0.1:3000` | Runner host から見た URL |

この構成では `CI_REGISTRY`, `CI_REGISTRY_IMAGE`, `SEEDSHIFT_IMAGE_REPOSITORY` は設定不要。pipeline 内では自動的に `localhost/seedshift-radio` を使う。

| `SEEDSHIFT_WEB_ADMIN_PASSWORD` | `********` | 必須。Masked / Protected |
| `SEEDSHIFT_WEB_SESSION_SECRET` | `********` | 必須。32 byte 以上を目安にランダム生成し Masked / Protected |

#### 3.7.3 ホスト固定ディレクトリを使う構成

既定では Podman managed volume `seedshift-radio-data` を使う。バックアップや運用都合で host path を固定したい場合だけ、以下を追加する。

| 変数 | 設定例 | 備考 |
|---|---|---|
| `SEEDSHIFT_RADIO_DATA_VOLUME` | `/srv/seedshift-radio/data` | host path を bind mount として使う |
| `SEEDSHIFT_RADIO_CONFIG_PATH` | `/var/lib/seedshift-radio/config/config.json` | 通常は既定値のまま |

host path を使う場合は、container 内 UID `10001` が書き込めるようにする。

```sh
sudo mkdir -p /srv/seedshift-radio/data/config
sudo chown -R 10001:10001 /srv/seedshift-radio/data
```

#### 3.7.4 MusicGen 生成物を残す構成

`deploy-musicgen` の `/data` を pipeline から固定したい場合だけ、以下を追加する。

| 変数 | 設定例 | 備考 |
|---|---|---|
| `MUSICGEN_DATA_VOLUME` | `/srv/seedshift-radio/musicgen` | host path を bind mount として使う |
| `MUSICGEN_HOST_BIND` | `0.0.0.0` | 必要な公開範囲へ絞る |
| `MUSICGEN_HOST_PORT` | `28080` | 既定どおりなら省略可 |

host path を使う場合は、rootless Podman の実行ユーザーが `/data` へ書き込めるようにする。

```sh
sudo mkdir -p /srv/seedshift-radio/musicgen
sudo chown -R <runner-user>:<runner-user> /srv/seedshift-radio/musicgen
```

Podman managed volume を使う場合は、`MUSICGEN_DATA_VOLUME=seedshift-radio-musicgen-data` のように volume 名を指定する。

#### 3.7.4.1 Irodori-TTS 参照音声を使う構成

Irodori-TTS-Server を追加する場合は、参照音声 directory と model cache を固定する。

| 変数 | 設定例 | 備考 |
|---|---|---|
| `IRODORI_TTS_HOST_BIND` | `127.0.0.1` | 標準。外部公開しない |
| `IRODORI_TTS_HOST_PORT` | `8088` | Server の provider 設定と合わせる |
| `IRODORI_TTS_VOICES_VOLUME` | `/srv/seedshift-radio/irodori/voices` | 同意済み参照音声だけを置く |
| `IRODORI_TTS_MODEL_VOLUME` | `seedshift-radio-irodori-models` | model / codec cache |
| `IRODORI_TTS_API_KEY` | `********` | 外部 bind 時のみ必須。Masked / Protected |

host path を使う場合は、rootless Podman の実行ユーザーが読み取れるようにする。参照音声 file 名や directory 名には実名や権利上センシティブな文字列を入れない。

#### 3.7.5 公開 URL を変える構成

Web の公開 port や smoke URL を変える場合の例。

| 変数 | 設定例 | 備考 |
|---|---|---|
| `SEEDSHIFT_WEB_PORT` | `3100` | Web container の `PORT` |
| `SEEDSHIFT_SMOKE_WEB_BASE_URL` | `http://127.0.0.1:3100` | Runner host から見た Web URL |
| `SEEDSHIFT_SMOKE_WEB_API_PROXY_BASE_URL` | `http://127.0.0.1:3100/api-proxy` | Runner host から見た proxy URL |

browser API base は same-origin `/api-proxy` に固定され、環境変数では変更できない。Server を同一 host の既定 port 以外で動かす場合だけ、server-side の `SERVER_INTERNAL_API_BASE_URL` を変更する。

## 4. Pipeline の流れ

### 4.1 自動実行

push 後、以下が順に実行される。

1. `validate`
   - `.gitlab-ci.yml` の YAML parse
   - `infra/compose/compose.prod.yml` の config 確認
2. `test`
   - Server unit / Docker backed test
   - Web typecheck / unit / e2e
   - MusicGen worker contract
3. `build`
   - `server-container-build`
   - `web-container-build`
4. `publish`
   - `server-container-publish`
   - `web-container-publish`
   - registry 設定時のみ push

### 4.2 手動 deploy

`main` ブランチでは以下が manual job になる。

1. `deploy-migrate`
   - Server image を使って Flyway migration を実行する
   - `SPRING_MAIN_WEB_APPLICATION_TYPE=none`
   - `SEEDSHIFT_RADIO_MIGRATION_ONLY=true`
   - `SEEDSHIFT_RADIO_JOBRUNR_ENABLED=false`
   - `JOBRUNR_JOB_SCHEDULER_ENABLED=false`
   - Spring 初期化と migration の成功後は ApplicationContext を close し、job を正常終了する
2. `deploy-app`
   - `scripts/ci/write-prod-env.sh` で deploy `.env` を生成する
   - `infra/compose/compose.prod.yml` を deploy directory へ配置する
   - registry 設定時は `podman --remote compose pull`
   - `podman --remote compose up -d`
3. `smoke-production`
   - `deploy-app` 成功後に自動実行される
   - Server health、Web `/`、Web proxy 経由 health、container 起動状態を確認する

## 5. 手動 deploy 操作

### 5.1 GitLab UI から実行

1. 対象 branch が `main` であることを確認する
2. Pipeline の test / build / publish が成功していることを確認する
3. `deploy-migrate` を手動実行する
4. `deploy-migrate` 成功後、`deploy-app` を手動実行する
5. `smoke-production` が成功することを確認する
6. `http://<server-host>:3000/` をブラウザで開く

### 5.2 Runner host で確認するコマンド

```sh
podman --remote ps --all
podman --remote logs seedshift-radio-server
podman --remote logs seedshift-radio-web
```

ログ確認時は `radioName`, letter body, prompt, API key, 管理トークン, DB password をチャットや issue に貼り付けない。

## 6. Deploy 後確認

Runner host:

```sh
curl -fsS http://127.0.0.1:8080/api/health
curl -fsS http://127.0.0.1:3000/
curl -fsS http://127.0.0.1:3000/api-proxy/api/health
SEEDSHIFT_SMOKE_WEB_BASE_URL=http://127.0.0.1:3000 sh scripts/smoke-admin-session.sh
```

利用端末:

```text
http://<server-host>:3000/
```

確認観点:

- Web の初期画面が表示される
- `/letters`, `/settings`, `/monitor` が表示できる
- 未認証の `/settings` と `/monitor` は `/admin/login` へ移動する
- `scripts/smoke-admin-session.sh` が未認証 `401`、session 発行、CSRF 拒否、認証済み管理 API proxy、logout を確認できる
- 管理系画面では管理 token、login password、session secret を `NEXT_PUBLIC_*` や browser storage へ出さない
- API/SSE は `/api-proxy` 経由で通信できる
- `podman --remote ps` で `seedshift-radio-server` と `seedshift-radio-web` が起動している

## 7. Rollback 手順

### 7.1 Registry を使う場合

1. 直前成功 pipeline の commit SHA を確認する
2. deploy runner の deploy `.env` を開く
3. `SEEDSHIFT_SERVER_IMAGE` と `SEEDSHIFT_WEB_IMAGE` を直前成功 tag に戻す
4. 以下を実行する

```sh
podman --remote compose --env-file <deploy-dir>/.env -f <deploy-dir>/compose.yml pull
podman --remote compose --env-file <deploy-dir>/.env -f <deploy-dir>/compose.yml up -d
```

### 7.2 Local image fallback の場合

1. 直前成功 tag が local Podman storage に残っていることを確認する

```sh
podman --remote images localhost/seedshift-radio/server
podman --remote images localhost/seedshift-radio/web
```

2. deploy `.env` の image tag を直前成功 tag に戻す
3. `pull` せずに起動する

```sh
podman --remote compose --env-file <deploy-dir>/.env -f <deploy-dir>/compose.yml up -d
```

DB migration 後の rollback はスキーマ後方互換を前提にする。破壊的 migration がある場合は、DB backup / restore 手順を別途用意する。

## 8. よくある失敗と対応

| 症状 | 原因 | 対応 |
|---|---|---|
| `invalid reference format` | image repository が空 | 最新 CI では local fallback 済み。`SEEDSHIFT_IMAGE_REPOSITORY` を空文字で上書きしていないか確認 |
| `Missing required environment variables` | 必須 CI/CD Variables 未設定 | DB password、管理 token、Web login password、session secret の job 別必須値を確認 |
| `CI_REGISTRY is not configured` と出る | GitLab Container Registry 未設定 | local image fallback なので通常は問題なし。外部 registry が必要なら registry 変数を設定 |
| `deploy-migrate` が DB 接続失敗 | PostgreSQL listen / DB 名 / ユーザー / パスワード不一致 | Runner host から `psql` で接続確認 |
| `deploy-migrate` で migration 成功後もプロセスが終了しない | 古い Server image に migration-only 終了制御がない | `SEEDSHIFT_RADIO_MIGRATION_ONLY=true` を含む最新 commit の Server image が publish されていることを確認 |
| `deploy-app` 後に Web が見えない | firewall / port / container 起動失敗 | `3000/tcp`, `podman --remote ps`, `podman --remote logs seedshift-radio-web` を確認 |
| Web は表示されるが API が失敗 | `/api-proxy` から Server へ到達できない | `curl http://127.0.0.1:3000/api-proxy/api/health` と Server logs を確認 |
| 管理ログイン後も `401` / `403` | cookie、Origin、CSRF、Web 認証変数の不一致 | HTTPS、`SEEDSHIFT_WEB_ADMIN_PASSWORD`, `SEEDSHIFT_WEB_SESSION_SECRET`、`/api/auth/session` を確認。秘密値はログへ出さない |
| `compose pull` が失敗 | registry 認証または repository 不一致 | registry を使わない場合は `CI_REGISTRY` を未設定にし、local fallback を使う |
| `deploy-musicgen` 後に生成物が消える | `MUSICGEN_DATA_VOLUME` 未設定で container-local `/data` を使っている | GitLab CI/CD Variables に `MUSICGEN_DATA_VOLUME` を設定し、必要な host path または Podman volume を準備 |
| `deploy-musicgen` が `/data` 書き込み権限で失敗 | host path の所有者・権限不足 | host path の owner / mode / SELinux label を確認し、CI で指定した `MUSICGEN_DATA_VOLUME` と一致させる |
