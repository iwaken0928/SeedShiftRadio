# SeedShiftRadio 依頼テンプレート

## 標準形

```text
doc/15_設計差分棚卸しと段階実装計画.md を起点に、未実装項目を 1〜2 件選んで実装して。
広い再調査は避け、対象項目に必要な設計書だけ確認して進めて。
必要ならサブエージェントに適切に割り振って作業して。

必ず以下まで完了して:
- コード修正
- 関連設計書更新
- 必要なテストと確認手順の実施
- 残課題と次の候補の整理

完了時は、着手した項目、変更ファイル、実行した確認コマンド、残リスクを簡潔に報告して。
```

## Web UI 中心

```text
doc/15 と doc/03 を起点に、/settings か /monitor の未実装項目を 1 件選んで実装して。
既存の実装状況を踏まえ、広い再調査はせず関連設計だけ確認して進めて。
必要なら web / qa のサブエージェントに分担して、
- UI実装
- Playwright または Vitest
- 設計書更新
まで完了して。
```

## Server / Runtime 中心

```text
doc/15 を起点に、doc/05 または doc/13 に関連する未実装項目を 1 件選んで実装して。
runtime 影響があるので、対象設計と現在の実装差分を最小限確認したうえで進めて。
必要なら server / qa のサブエージェントに分担して、
コード修正、関連設計書更新、テスト実施まで完了して。
```

## 差分確認込み

```text
doc/15 と関連設計書、現状コードから差分を確認し、
今すぐ着手すべき未実装項目を 1〜2 件選んで実装して。
広い棚卸しのやり直しは不要で、対象範囲だけ見て進めて。
必要ならサブエージェントへ割り振って、
実装、設計書更新、確認手順の実施まで終えて。
```

## 書くと安定する指定

- 起点ドキュメント: `doc/15`
- 一度に扱う件数: `1〜2 件`
- 広い再調査の抑制
- 設計書更新の義務
- サブエージェント利用可否
- 完了時に欲しい報告形式
